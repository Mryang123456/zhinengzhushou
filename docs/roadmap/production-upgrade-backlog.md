# 智行助手生产级升级台账

> 最近更新：2026-11-24  
> 目标：统一记录此前讨论、排查和面试复盘中提出的升级事项，避免遗漏、重复建设或把规划能力误认为已实现能力。  
> 维护规则：功能、Prompt、工具、数据结构或部署方案发生变化时，必须同步更新状态、验收证据和关联提交。

## 1. 状态定义

| 状态 | 含义 |
| --- | --- |
| 已完成 | 已有实现、自动化验证或明确文档证据 |
| 部分完成 | 已有基础能力，但离生产级验收仍有明确缺口 |
| 待升级 | 尚未实现，或只有设计说明 |
| 按需演进 | 当前不影响 Python Agent，等真实业务需求出现后再建设 |

优先级：

- **P0**：影响数据安全、回答正确性、状态一致性或故障恢复，上线前必须解决。
- **P1**：影响可维护性、质量上限、规模化和持续迭代，应进入近期版本。
- **P2**：体验、效率、成本与工程完善，可分阶段实施。

当前基线共记录 **96 个唯一升级项**：P0 30 项、P1 44 项、P2 22 项。状态分布为：待升级 37 项、部分完成 47 项、按需演进 5 项、已完成 3 项、已完成/持续验证 4 项。

## 2. 当前能力基线

当前项目已经具备以下基础能力：

- React + TypeScript + Vite 中文聊天前端，支持 SSE、会话、引用、查询过程和本地持久化。
- FastAPI + LangGraph Agent Loop，包含意图分析、任务规划、工具执行、观察、证据复核和回答交付。
- DeepSeek 等 OpenAI 兼容模型的 Provider 封装。
- 本地工具、Skill、MCP、工具语义检索、动态候选白名单、参数校验和高风险审批基础。
- PostgreSQL、pgvector、混合检索、父子/邻居 Chunk、Cross-Encoder 可选重排和 RAG 评测。
- 长期记忆、上下文预算、结构化历史摘要和 LangGraph Checkpoint。
- JWT、多用户会话隔离、Chat Run、PostgreSQL advisory lock、幂等请求和 SSE 事件恢复基础。
- Redis 多实例限流与 MCP 审批令牌基础。
- 单元测试、意图/规划/RAG fixture 回归和 GitHub Actions。
- 独立 Spring Boot 基础服务，当前只做健康检查、Trace 和 Python Agent 就绪探测，对 Python 零侵入。

这份基线不代表所有能力均已达到生产级，具体缺口以以下台账为准。

| 追问澄清 | 缺少对象时不猜测 | 上文只有一个明确事件仍再次追问 | 单一事件继承，多事件澄清，实体纠正覆盖旧实体 |
| 时效问题强制搜索 | 新闻、财报、天气需要新数据 | 普通知识和润色任务也被联网 | 直接回答和写作 Case 明确禁止网页工具 |
| 工具失败安全 | 失败不能成为证据 | 整轮回答被清空或失败结果支撑结论 | 失败结果保留可观测性，但绝不进入有效证据 |
| 重试与 Checkpoint | 允许断流重试 | 服务端重复写入用户问题或草稿污染历史 | message_id/attempt_id 幂等，拒绝草稿不进入 Checkpoint |
| 多标签页同步 | 本地聊天持久化 | 两页快照互相覆盖 | 合并写入、版本控制和服务端权威同步 |
| 多实例会话 | 多 Worker 提升吞吐 | 同会话两条消息丢一轮 | 会话队列、锁/租约、序号和 CAS 同时存在 |

## 7. 推荐实施顺序

### 第一阶段：质量与状态底座

1. Prompt Registry 和 Run Manifest（P0-PRM-01 已完成）。
2. 真实模型旧新 Prompt A/B 与 Badcase 回流。
3. 会话序号、Checkpoint CAS、Worker 租约和心跳。
4. 外部写工具幂等、`outcome_unknown` 和原生 HITL。
5. MCP 容器隔离、密钥治理和备份恢复演练。

### 第二阶段：规模化能力

1. API/Worker 解耦和持久任务队列。
2. 工具注册中心、契约版本、灰度和下线。
3. DAG 调度、并行执行和部分失败语义。
4. RAG Gold Set、Live 门禁和 Embedding/Cross-Encoder 生产部署。
5. OpenTelemetry、SLO、告警和成本预算。

### 第三阶段：体验与业务演进

1. 回答丰富度和查询过程体验。
2. 前端 E2E、压力、断流和多标签页测试。
3. Skill 和子 Agent 的版本、进度及持久化。
4. LLM Wiki 增量更新和 Claim 证据映射。
5. 有明确业务需求后，逐步让 Java 接管身份、租户、会话和业务事务。
